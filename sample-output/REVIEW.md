# 评审核查与修订

评审提出的测试证据与可维护性问题成立；没有复现出四条核心底线的行为失败。分数区间是评审意见，不能由本项目自行证实，也不承诺任何外部评分。

| 评审项 | 核查结论与已完成修订 |
|---|---|
| B 像针对考题设计 | 原句确实通过 `for` 词尾提示走 1000ms；这是允许的规则，但单独不足以说明泛化。新增四组不同音频时长的集成案例，其中 `I was thinking…`、`Perhaps tomorrow...`、`我想想…` 不依赖英语功能词表，均在 700ms 停顿内不提交、不播放，完成后在 400ms 内 endpoint。 |
| session 文件太集中 | 原文件超过千行；现 `session.rs` 为 196 行，输入、generation、生命周期、配置和 handle 分到五个私有模块。取消仍在一个 owner 转换内完成，无新增锁、任务或跨通道等待；关闭等待单独命名为 `shutdown`。 |
| UTF-8 测试名过度承诺 | 原测试只验证 ASCII 和重复包。已准确重命名，并新增中文 `周五 ` 的非法码点起止范围、越界范围、拒绝后的状态不变和合法范围完整播放测试。 |
| A/B 时间常数 | A 改为读取 trace 中的配置，扣除 ASR final、LLM/TTS 固有延迟，再限制额外调度 ≤两个节拍；覆盖首包组合 0/0、13/47、80/60、150/110ms。B 使用输入 PCM 采集真值计算结束时刻；400ms 是用户计划的外部验收上限，保留这一约束，同时检查配置阈值加两个节拍的更紧预算。 |
| 单 owner 串行化 | 描述属实，是设计选择。并发 Provider 的取消、迟到、异常与关闭通过消息交错测试；没有把这些称为多线程共享内存竞争，也没有为评分引入不必要的共享播放器状态。 |
| 停播阶段为 0ms | 描述属实，属于同步模拟 sink 语义。README/DESIGN 已突出：这不包含设备缓冲排空、stop ACK 或声学停声时间；用户开口到模拟停播仍测得 120ms。 |

两点措辞需要纠正：120ms 连续语音确认是防抖，WebRTC VAD 的 hangover 是另一个机制；原默认套件的 26 项已经包含真实时钟打断和 8-session 压测，不能再额外加算。目前默认 28 项、全部 features 29 项，矩阵中的多组输入和 32 次属性案例是测试内部执行次数。

验证：每个原子提交通过暂存快照的完整格式、Clippy、默认/全部 features 测试、release 构建及 hook 自检。A–E 的 JSONL、指标、播放账本、已消费 WAV、Mermaid 和生命周期报告在重构前后逐字节相同，交付 C trace 也保持不变，独立 replay 成功。具体源码 commit、实际耗时和每份产物的 SHA-256 保存在 `review-validation.json`。

保留的边界：无标点、无不完整提示的未知文本使用 600ms fallback，不能保证所有 700ms 犹豫都安全；本实现没有语义完整度模型，也未验证真实设备/AEC 或托管 CI。以上限制与原工程边界一致，测试通过不等于真实声学系统已达到生产准确率。
